프롬프트에 없지만 들어간 것 (동작 영향 있음):

- 서버 요청은 `send()` 줄로 **한 번에 하나, 누른 순서대로** 나간다 (연달아 바꿔도 마지막 값이 남는다).
- 완료 토글이 빈 본문 `{}`(서버가 뒤집기) 대신 `{done: true|false}`를 보낸다. 서버는 이미 받는다 (`src/index.ts:1875`).
- 목록·할 일 GET을 차례가 아니라 함께 부른다.
- 직전과 같은 HTML이면 DOM을 다시 쓰지 않는다 (`setHtml`). 다시 그릴 때 포커스·입력 중 글자를 되살린다.
- 정렬·보기 전환도 가진 목록으로 먼저 그리고 뒤에서 다시 읽는다 (화면 쪽 `arrange()`는 서버 `arrangeTasks`와 같은 규칙).
- 제목·메모 칸은 `focusout`에서도 저장한다 (값이 같으면 아무 일도 없다).
- 추가 실패 알림이 `alert`에서 `uiToast`로 바뀌었고, 쓴 글자를 입력칸에 돌려놓는다.

## 5. 남은 한계

- **브라우저 화면 확인을 못 했다.** 하네스는 가짜 DOM이라 실제 포커스 되살리기(`keepFocus`/`restoreFocus`), `focusout` 저장, 한글 조합 중 Enter 뒤 입력칸 비우기(`clearInput`), `pointer-events` 잠금의 체감은 검증되지 않았다. Merlin이 브라우저로 볼 것: 시간 고르면 줄에 바로 뜨는지, 추가·삭제 직후 연달아 클릭해도 다른 줄에 닿지 않는지, 제목 입력 중 다른 변경의 응답이 와도 글자·커서가 남는지, 한글 제목 Enter 추가.
- 반복 할 일의 다음 회차는 화면에서 미리 만들지 않는다. 응답 뒤 다시 읽을 때(왕복 1회 뒤) 나타난다.
- 한 할 일에 변경이 여러 개 줄 서 있을 때 앞의 것이 실패하면, 그 할 일은 실패한 변경 이전 모습으로 통째로 돌아간다 (뒤에 누른 값도 화면에서 잠깐 사라진다). 줄이 다 빠진 뒤의 다시 읽기가 서버 값으로 맞춘다.
- 요청을 하나씩 보내므로 느린 망에서 빠르게 여러 번 바꾸면 서버 저장은 그만큼 늦게 끝난다 (화면은 즉시). 그 사이 탭을 닫으면 줄 서 있던 변경은 사라진다.
- 다른 기기·다른 사람이 바꾼 내용은 내 변경이 다 끝난 뒤의 새로고침에서야 보인다.
- 관리자 화면(담당자 필터·다른 사람 할 일 만들기)의 임시 줄은 하네스에서 돌리지 않았다 (일반 사용자 경로만 검증).
